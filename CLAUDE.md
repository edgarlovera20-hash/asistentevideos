# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Heavenly Dreams Meeting AI" (applicationId `com.aistudio.heavenlyaimeeting.pzxq`) — a native Android app (Kotlin + Jetpack Compose) that records meetings, transcribes them, and runs AI analysis (summary, agreements, tasks, risks, sentiment). Originally generated by Google AI Studio; this repo has since replaced most of the originally-simulated functionality with real implementations (see "Fallback conventions" below for what's still template-based on purpose).

## Build, run, test

This project only builds reliably from **PowerShell**, not Git Bash — running `gradlew` from Git Bash on this toolchain fails with `IOException: Unable to establish loopback connection`. Always invoke Gradle via the `PowerShell` tool, not `Bash`.

`JAVA_HOME` is not set globally in this environment — set it to Android Studio's bundled JBR before any Gradle invocation:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat :app:compileDebugKotlin --console=plain
.\gradlew.bat :app:assembleDebug --console=plain
.\gradlew.bat :app:testDebugUnitTest --console=plain
```

- Debug APK output: `app/build/outputs/apk/debug/app-debug.apk`
- `ExampleRobolectricTest` and `GreetingScreenshotTest` (Roborazzi) are AI-Studio boilerplate and currently fail on this Windows environment with a Robolectric native-graphics loader error unrelated to app code — don't treat their failure as a regression signal. `ExampleUnitTest` is a real passing sanity check.
- No lint/format command is configured beyond the Kotlin compiler itself.

### Secrets

The Gradle Secrets plugin reads `GEMINI_API_KEY` from a local `.env` file (gitignored; `.env.example` is the template) into `BuildConfig.GEMINI_API_KEY` — this is the build-time default Gemini key. All other AI/image provider keys (Anthropic, OpenAI, Kimi, NVIDIA NIM, Ollama/LM Studio URLs) are entered by the user at runtime in the in-app **Ajustes IA** screen and persisted via plain `SharedPreferences` (see `AiProviderSettings`, `ImageProviderSettings`) — they are never committed.

## Architecture

### Data flow: MVVM + Repository

`MeetingViewModel` (one large `AndroidViewModel`, owns almost all app state as `StateFlow`) → `MeetingRepository` → `MeetingDao` (Room) + injected services. `RemindersViewModel` and `AiSettingsViewModel` are the only other ViewModels, each scoped to their own screen. There's no dependency injection framework — services are constructed directly with default-arg constructors (e.g. `MeetingRepository(dao, aiService, geminiService, transcriptionService)`), which is also how tests would substitute fakes if any existed.

### Room database (`data/db/`)

`AppDatabase` is a singleton (`getDatabase(context)`), currently **version 6**, using `fallbackToDestructiveMigration()` — schema changes wipe local data rather than migrate it. This is an accepted tradeoff for a personal-use sideloaded app; bump the version and don't add a real `Migration` unless that changes. Entities: `MeetingEntity`, `ParticipantEntity`, `TranscriptSegmentEntity`, `ActionTaskEntity`, `AgreementEntity`, `ChatMessageEntity`, `VisualAssetEntity`, `MeetingSummaryEntity`, `AuditLogEntity`, `ReminderEntity`.

### Multi-provider AI abstraction (`data/ai/`)

`AiTextService` is the interface for the four AI text operations (`analyzeMeeting`, `chat`, `generateDocument`, `translate`) that `MeetingRepository` calls — it does **not** cover audio transcription (Gemini-only, `GeminiAudioTranscriptionService`) or Visual IA's static template assets, which are separate concerns by design.

- `GeminiTextService` — thin adapter over the pre-existing `GeminiMeetingService` (in `data/api/`, not `data/ai/`) — that class's internal logic (prompt building, response parsing, fallback generation) is intentionally left untouched and reused via import rather than duplicated.
- `AnthropicTextService` — its own client (Anthropic's Messages API differs from the others).
- `OpenAiCompatibleTextService` — one parameterized client (`baseUrl`, `apiKey`, `model`) reused for every provider that speaks the OpenAI `/chat/completions` shape: OpenAI, Kimi (Moonshot), NVIDIA NIM, and self-hosted Ollama/LM Studio.
- `AiProviderSettings` stores the active provider + per-provider key/URL/model in SharedPreferences; `AiServiceFactory.create(context)` builds the active one, `AiServiceFactory.createFor(context, provider)` builds an arbitrary one (used by the "Confirmar y probar conexión" test button so a provider can be verified without switching to it first).
- Shared prompt text, the `---HEADER---`-section response parser, and honest fallback-message builders live in `AiPromptTemplates.kt` — reused by every non-Gemini provider so they all produce the same `MeetingAnalysisResult` shape.

### Fallback conventions — read before touching AI call sites

Every AI call site follows the same pattern: try the real network call, and on failure return an **honest** fallback string/result stating the AI call failed — never a fabricated-but-plausible answer. Fallback text always starts with `"No se pudo conectar con..."` — this exact prefix is checked by the UI (e.g. the settings screen's connection test) to distinguish a real answer from a fallback, so don't reword it without updating those checks. `describeError(e)` (in `GeminiMeetingService.kt`) turns an exception into a short HTTP-code-plus-body detail string that gets appended to these fallback messages instead of a generic "check your connection."

This same honesty principle extends to features that are still template-based rather than AI-driven: the Visual IA screen's "30 skills" catalog and most of its asset generation are static local templates, not live model calls — this is intentional (an earlier audit found them making false AI-generation claims and relabeled them), so don't reintroduce fake-AI copy there. The one real exception is the "Generar imagen real" card, wired to `NvidiaImageService` (FLUX.1-schnell via NVIDIA NIM) — assets it creates get `VisualAssetEntity.imageFilePath` set and render via Coil `AsyncImage`; everything else renders via the local `VisualAssetCanvasRenderer`.

### Google integrations (`data/auth/`, `data/api/`)

`GoogleAuthManager` wraps Google's Authorization API (Identity Services) for a combined `calendar.readonly` + `drive.file` scope grant, requiring a "Web" OAuth client ID as `requestOfflineAccess`'s server client ID (a library quirk, not a real backend) — see the class doc for why the token is cached in plain (not Encrypted) SharedPreferences. `GoogleCalendarService` and `GoogleDriveService` are thin REST clients used by `CalendarSyncWorker` (WorkManager, 15-min periodic) and the meeting detail screen's "Guardar en Drive" button respectively.

### Reminder pipeline (`data/notifications/`, `data/work/`)

`ReminderEntity` is deliberately source-agnostic (`source: "CALENDAR" | "WHATSAPP"`, deduped on `sourceRefId`) so both `CalendarSyncWorker` and `WhatsAppNotificationListenerService` feed the same `ReminderNotifier`/`AlarmManager` scheduling path. The WhatsApp listener runs a cheap keyword pre-filter before ever calling the active `AiTextService` to classify a message as a meeting mention — most chat traffic never reaches the AI. `@Insert(onConflict = IGNORE)` (not `REPLACE`) on reminder upsert is intentional: it keeps an already-notified reminder from re-firing on the next sync cycle.

### Retry/timeout conventions

`retryIO()` (in `GeminiMeetingService.kt`, reused across providers) is a simple manual retry loop for ordinary text API calls. Image generation (`NvidiaImageService`) deliberately does **not** use it — cold-start diffusion generation can take over a minute, so retrying would multiply an already-long wait; it uses long OkHttp timeouts and a single attempt instead.

### `ponytail:` comments

Comments prefixed `ponytail:` mark a deliberate simplification with a known ceiling and the upgrade path (e.g. plain SharedPreferences instead of EncryptedSharedPreferences, `IGNORE` conflict strategy accepting stale event times on reschedule). Keep the convention when making similar tradeoffs — it signals "chosen", not "overlooked."
